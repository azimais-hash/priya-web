# Mindfully Priya website - house rules for Claude

This is Priya Khan's coaching website, www.mindfullypriya.com. Priya asks for
changes in plain English. She is not a developer, so explain what you changed in
plain words and never ask her to run commands.

## How a change goes live

1. Work on a new branch, never on `main`.
2. Make the change, run `python3 build.py` (needs `pip install markdown`) and
   check it prints "built N pages" with no error.
3. Commit, push the branch and open a pull request. Title it in plain words,
   for example "Lowry page: real booking link".
4. Vercel adds a preview link to the pull request within a minute or two. Give
   Priya that link so she can check it on her phone.
5. Azim reviews and merges. Merging to `main` publishes the live site. Never
   merge, force-push or change repository settings yourself.

## Where things are

- `content/` - one Markdown file per page; the file path is the web address
  (`content/lowry.md` is `/lowry`, `content/post/x.md` is `/post/x`).
- Front matter at the top of each page: `title` and `description` (what Google
  shows), `heading`, `lede`, `eyebrow`, `image`, `layout` (`page`, `post`, `html`).
- `layout: html` pages (such as `lowry.md`) are hand-written HTML. Edit the text
  inside the tags and leave the tags and `class` names alone.
- `build.py` - the `LINKS` table near the top holds every booking and form link.
  Pages use `{{LINK:NAME}}`; change a link once in `LINKS`, never in the pages.
- `templates/` - the header, menu and footer shared by every page.
- `assets/site.css` - the whole design. Only touch it if Priya asks for a design change.
- `public/images/` - photos. New photos go here, resized to 1600px wide or less.
- `public/` is generated by `build.py`; edit `content/` and rebuild.

## Drafts and hidden pages

- `draft: true` - the page shows an approval bar and only appears on preview
  links. The live site leaves it out completely. Remove `draft: true` only when
  Priya says the page is approved.
- `hidden: true` - the page is live but kept out of Google (noindex, nofollow),
  the sitemap and the menus. `/lowry` is hidden: never link to it from any other page.
- New blog posts start as `draft: true` with a `date:` line.

## Writing rules

- When Priya supplies copy, use it word for word. Do not rewrite, shorten or add
  to it unless she asks.
- British English. Never use em or en dashes; use a plain hyphen.
- Never write the "X, not Y" pattern (for example "a person, not a process").
- Keep pages calm and simple, no animations, and check they read well on a phone.

## Never touch

- `api/` - the contact and review forms. Their email passwords live in Vercel,
  never in this repository; never add passwords, keys or tokens to any file.
- `vercel.json` - redirects that keep old Wix addresses working, and the build settings.
- Analytics: the site uses Vercel Web Analytics only. Do not add any other
  tracking, cookies or third-party scripts; Priya must agree to that first.
- The 30-minute call (`BOOK_DISCOVERY`) is the general booking link. The Lowry
  page must use its own `LOWRY_BOOKING` link and never the 30-minute call.
